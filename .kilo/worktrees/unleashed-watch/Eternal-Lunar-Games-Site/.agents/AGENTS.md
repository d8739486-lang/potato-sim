# Workspace Rules

## Interactive Prompts
- **Hard Constraint**: Если в процессе планирования или выполнения задачи возникают открытые вопросы, требующие решения пользователя (например, выбор архитектуры, способа хранения данных или дизайна), **ВСЕГДА** используйте инструмент `ask_question`.
- Не оставляйте вопросы текстом внутри `implementation_plan.md` или в обычных ответах.
- Предоставьте пользователю 3-4 конкретных варианта ответа (в виде опций) для быстрого выбора.
- После выбора пользователя, продолжайте выполнение задачи на основе этого выбора.

## Auto-Deploy to Vercel
- После **каждого** завершённого изменения кода в этом проекте — запускай деплой командой:
  ```
  npx vercel --prod --yes
  ```
  в директории `c:\Users\user\Desktop\Projects\My-Games-Site`.
- Не спрашивай разрешения на деплой — делай его автоматически.
- Сообщай пользователю итоговую production-ссылку после завершения деплоя.

## Shell Preference (Git Bash / PowerShell)
- **Preference**: Предпочитать синтаксис и выполнение через Git Bash (bash/sh) везде, где возможно.
- **PowerShell**: Использовать PowerShell только для тех команд, которые отсутствуют в Bash или требуют специфичных Windows/PowerShell командлетов.

## Token Efficiency & Ultra-Short Responses
- **Hard Constraint**: Экономить токены до 10x.
- **Формат ответов**: Никаких вступлений, приветствий, вежливых вводных слов и развёрнутых отчётов.
- **После выполнения задачи**: Выдавать строго 1-2 короткие строчки ответа + ссылку (если есть).
- **Внутренняя работа**: Не вызывать дублирующиеся инструменты, делать диффы минимальными.
